## 1. 硬约束（违反任何一条都会造成实际损害）

1. **一次只发一条短命令。** 禁止多行脚本、禁止 heredoc、禁止长 `printf`。
   用户的 iOS SSH 客户端会在粘贴的行内**静默插入和吞掉空格**，已经因此把
   YAML 写成 `password:密码`（少一个空格，类型就从映射变成字符串，而且不报错）。
2. **占位符只能用纯 ASCII 字母数字下划线**（`PASTE_XXX`）。
   **绝对不要用 `<` `>`** ——那是 shell 重定向，上一轮因此把占位符文本写进了配置。
   更好的做法：**让脚本自己 `openssl rand -hex 16` 生成并打印**，用户不用改任何东西。
3. **重启服务之前先 `grep` 验证写进去的内容**，确认冒号后面有空格。
4. **不要让用户在手机上切代理去测试。** 用户手机挂在旧机场上，切换会让已登录的
   账号看到不同的出口 IP，这是真实代价。**iPad 是唯一可以随便测的设备**
   （它本来就走这个节点，出口 IP 不变）。
5. **不要把断线次数直接念给用户听。** 短于 5 分钟的重连是锁屏/切后台，不是故障。

## 4. 第一件事：验证 Brutal 是不是变慢的原因

**依据**：用户说刚搭好时速度好得多，而那时 Brutal 开着（基线 234/235 条连接
`tx: 18750000`），09-06 关掉了它。Brutal 的设计目的正是**为丢包链路准备的**
——无视丢包硬推；BBR 遇到 50% 丢包会把速率压到地板。

**按这个顺序做，一条一条发给用户：**

```
sed -i 's/^ignoreClientBandwidth: true/ignoreClientBandwidth: false/' /etc/hysteria/config.yaml
```

```
grep ignoreClientBandwidth /etc/hysteria/config.yaml
```

（必须打印 `ignoreClientBandwidth: false`，不是就停下。）

```
systemctl restart hysteria-server
```

```
systemctl is-active hysteria-server; ss -ulnp|grep 24443
```

然后让用户在 **iPad** 上开 `speed.cloudflare.com` 测一次，报回四个数：
**下载 / 上传 / 延迟 / 丢包**。

**对照基线（iPad / Wi-Fi / 09-06 23:00）：**

```text
下载 5.74 Mbps   上传 48.4 Mbps   延迟 358ms   抖动 226ms   丢包 50%
```

### 怎么判

- **明显变快** → Brutal 就是原因。**但这是取舍不是纯收益**：当初关它是为了治手机
  断线（§0.8 怀疑高速无视丢包的 UDP 流招来运营商 QoS）。**必须把这个取舍讲清楚，
  让用户自己选**，别替他决定。选了就记进 `paste-commands.md` §3 的实测表。
- **没变化** → 不是 Brutal。**把它改回 `true`**，然后进第 5 步。

**退回**：把 `false` 改回 `true`，重启。

## 7. 挂着没做、明确不要顺手做的

- `quic.maxIdleTimeout` 30s → 60s。审计已证明**只改服务端无效**

- `tune-hy2.sh`。审计列了 6 个问题，**建议不要在这台机器上用**
